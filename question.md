## 1. Объясните жизненный цикл HTTP-запроса в Yii2

**Вопрос:**  
Что происходит с момента получения HTTP-запроса до отправки ответа пользователю?

**Подробный ответ:**  
Жизненный цикл запроса в Yii2 обычно выглядит так:

1. Веб-сервер перенаправляет запрос на входной скрипт `web/index.php`.
2. Подключается автозагрузка Composer.
3. Загружается конфигурация приложения.
4. Создается объект приложения `yii\web\Application`.
5. Приложение получает компонент `request` и разбирает URL.
6. `urlManager` определяет маршрут, например `site/index`.
7. Создается нужный контроллер.
8. Выполняются фильтры и behaviors контроллера, например `AccessControl` или `VerbFilter`.
9. Вызывается action.
10. Action взаимодействует с моделями, сервисами, базой данных и формирует результат.
11. Результат преобразуется в объект ответа `response`.
12. Отправляются HTTP-заголовки и тело ответа.

Важно понимать, что Yii2 строится вокруг компонентов приложения. Многие этапы можно настраивать через конфигурацию: маршруты, обработку ошибок, формат ответа, сессии, логирование, кэширование и т.д.

## 2. В чем разница между Model, ActiveRecord и Form Model?

**Вопрос:**  
Чем отличаются `yii\base\Model`, `yii\db\ActiveRecord` и модели форм?

**Подробный ответ:**  
`yii\base\Model` - базовый класс для объектов, которые имеют атрибуты, правила валидации, сценарии и ошибки, но не обязательно связаны с таблицей базы данных.

`yii\db\ActiveRecord` наследуется от `Model` и добавляет связь с таблицей базы данных. Экземпляр ActiveRecord обычно представляет одну строку таблицы. Он умеет выполнять `find()`, `save()`, `delete()`, описывать связи через `hasOne()` и `hasMany()`.

Form Model - это обычная модель, чаще всего наследник `yii\base\Model`, которая описывает конкретную форму или пользовательский сценарий: логин, регистрацию, фильтр поиска, смену пароля, импорт файла. Она может не иметь прямого соответствия таблице.

Правильный подход:

- ActiveRecord использовать для работы с данными и связями таблиц.
- Form Model использовать для входных данных пользователя и сценариев валидации.
- Не складывать всю бизнес-логику в ActiveRecord, если она относится к процессу, а не к самой сущности.

## 3. Как работает валидация в Yii2?

**Вопрос:**  
Как Yii2 понимает, какие поля валидировать, и как добавить собственное правило?

**Подробный ответ:**  
Валидация описывается в методе `rules()` модели. Каждое правило определяет набор атрибутов, валидатор и дополнительные параметры.

Пример:

```php
public function rules()
{
    return [
        [['email', 'password'], 'required'],
        ['email', 'email'],
        ['password', 'string', 'min' => 8],
    ];
}
```

При вызове `$model->validate()` Yii2 берет активный сценарий модели, определяет список атрибутов, применяет к ним валидаторы и заполняет `$model->errors`, если есть ошибки.

Собственный валидатор можно описать методом:

```php
public function validateBalance($attribute)
{
    if ($this->$attribute < 0) {
        $this->addError($attribute, 'Баланс не может быть отрицательным.');
    }
}
```

И подключить его:

```php
['balance', 'validateBalance']
```

Также можно создать отдельный класс-валидатор, если правило используется в нескольких местах. Это предпочтительнее, когда логика сложная или переиспользуемая.

## 4. Что такое сценарии валидации?

**Вопрос:**  
Для чего в Yii2 используются scenarios и когда они полезны?

**Подробный ответ:**  
Сценарии позволяют определить, какие атрибуты модели активны и какие правила применяются в конкретном контексте.

Например, при регистрации пользователь должен указать email и пароль, а при обновлении профиля пароль может быть необязательным.

```php
public function scenarios()
{
    return [
        'register' => ['email', 'password'],
        'update' => ['email', 'name'],
    ];
}
```

Затем:

```php
$model->scenario = 'register';
```

Сценарии полезны, когда одна модель используется в нескольких операциях с разными наборами полей. При этом важно не злоупотреблять ими: если сценариев становится слишком много и модель превращается в набор противоречивых условий, лучше выделить отдельные Form Model.

## 5. Как работает ActiveRecord в Yii2?

**Вопрос:**  
Объясните принцип работы ActiveRecord и приведите пример запроса со связью.

**Подробный ответ:**  
ActiveRecord связывает PHP-класс с таблицей базы данных. Класс описывает таблицу через метод `tableName()`, а объект класса представляет строку таблицы.

Пример:

```php
class Order extends \yii\db\ActiveRecord
{
    public static function tableName()
    {
        return '{{%order}}';
    }

    public function getCustomer()
    {
        return $this->hasOne(Customer::class, ['id' => 'customer_id']);
    }
}
```

Использование:

```php
$orders = Order::find()
    ->with('customer')
    ->where(['status' => Order::STATUS_PAID])
    ->all();
```

Метод `with()` выполняет жадную загрузку связи и помогает избежать проблемы N+1, когда для каждой записи выполняется отдельный запрос к связанной таблице.

ActiveRecord удобен, но его нужно использовать аккуратно. Для сложных отчетных запросов, массовых обновлений или тяжелой аналитики иногда лучше использовать Query Builder или SQL напрямую.

## 6. Что такое проблема N+1 и как ее решить в Yii2?

**Вопрос:**  
Что такое N+1 query problem и как ее обнаружить?

**Подробный ответ:**  
Проблема N+1 возникает, когда приложение сначала получает список записей одним запросом, а затем для каждой записи отдельно загружает связанную сущность.

Пример проблемы:

```php
$orders = Order::find()->all();

foreach ($orders as $order) {
    echo $order->customer->name;
}
```

Если заказов 100, будет выполнен 1 запрос для заказов и 100 дополнительных запросов для покупателей.

Решение:

```php
$orders = Order::find()
    ->with('customer')
    ->all();
```

Yii2 загрузит покупателей отдельным оптимизированным запросом и сопоставит их с заказами.

Обнаружить проблему можно через Yii Debug Toolbar, логирование SQL-запросов, профилирование или анализ медленных запросов в базе данных.

## 7. Что такое компоненты приложения?

**Вопрос:**  
Что такое application components в Yii2 и как они конфигурируются?

**Подробный ответ:**  
Компоненты приложения - это объекты, доступные через `Yii::$app`. Например:

- `Yii::$app->db`
- `Yii::$app->request`
- `Yii::$app->response`
- `Yii::$app->cache`
- `Yii::$app->user`
- `Yii::$app->mailer`

Они конфигурируются в файле конфигурации приложения:

```php
'components' => [
    'cache' => [
        'class' => yii\caching\FileCache::class,
    ],
    'db' => [
        'class' => yii\db\Connection::class,
        'dsn' => 'mysql:host=localhost;dbname=app',
        'username' => 'user',
        'password' => 'password',
    ],
]
```

Компоненты удобны для инфраструктурных сервисов, которые действительно являются частью приложения. Но бизнес-сервисы не всегда стоит глобально складывать в `Yii::$app`, особенно если это усложняет тестирование и повышает связанность кода.

## 8. Как работает DI container в Yii2?

**Вопрос:**  
Для чего нужен контейнер зависимостей и как его использовать?

**Подробный ответ:**  
DI container в Yii2 управляет созданием объектов и внедрением зависимостей. Он позволяет конфигурировать, какой класс должен использоваться при запросе интерфейса или базового класса.

Пример:

```php
Yii::$container->set(
    PaymentGatewayInterface::class,
    StripePaymentGateway::class
);
```

После этого объект, которому нужен `PaymentGatewayInterface`, может получить реализацию через конструктор:

```php
class PaymentService
{
    public function __construct(
        private PaymentGatewayInterface $gateway
    ) {}
}
```

Контейнер помогает снизить связанность и упростить тестирование. В тестах можно подменить реализацию интерфейса на fake или mock.

Важно не превращать контейнер в скрытый service locator. Лучше передавать зависимости явно через конструктор, чем внутри класса обращаться к `Yii::$container` или `Yii::$app` без необходимости.

## 9. Как устроены миграции в Yii2?

**Вопрос:**  
Для чего нужны миграции и чем отличаются методы `up()`/`down()` от `safeUp()`/`safeDown()`?

**Подробный ответ:**  
Миграции позволяют версионировать изменения структуры базы данных: создание таблиц, индексов, внешних ключей, добавление колонок, изменение типов.

Методы `up()` и `down()` выполняют изменения без автоматической транзакции.

Методы `safeUp()` и `safeDown()` Yii2 пытается выполнить внутри транзакции, если используемая СУБД и конкретные операции это поддерживают.

Пример:

```php
public function safeUp()
{
    $this->createTable('{{%product}}', [
        'id' => $this->primaryKey(),
        'name' => $this->string()->notNull(),
        'created_at' => $this->integer()->notNull(),
    ]);
}

public function safeDown()
{
    $this->dropTable('{{%product}}');
}
```

Хорошая миграция должна быть воспроизводимой, понятной и безопасной для применения на разных окружениях. Для больших таблиц нужно учитывать блокировки, время выполнения и стратегию выкладки.

## 10. Как реализовать RBAC в Yii2?

**Вопрос:**  
Что такое RBAC и как Yii2 помогает его реализовать?

**Подробный ответ:**  
RBAC - role-based access control, модель контроля доступа на основе ролей и разрешений. В Yii2 есть компонент `authManager`, который может хранить роли, permissions и связи между ними в PHP-файлах или базе данных.

Пример логики:

- Permission `createPost`.
- Permission `updatePost`.
- Role `author`, которая имеет право `createPost`.
- Role `admin`, которая наследует права `author` и дополнительно имеет `updatePost`.

Проверка доступа:

```php
if (Yii::$app->user->can('updatePost', ['post' => $post])) {
    // Доступ разрешен
}
```

Для объектных правил можно использовать `Rule`, например чтобы пользователь мог редактировать только собственную запись.

RBAC полезен, когда прав много, роли меняются, а доступ нельзя описать простыми условиями в контроллерах. Для простых проектов иногда достаточно `AccessControl` и проверок ролей пользователя.

## 11. Как защититься от CSRF, XSS и SQL-инъекций в Yii2?

**Вопрос:**  
Какие механизмы безопасности предоставляет Yii2?

**Подробный ответ:**  
Yii2 предоставляет несколько уровней защиты.

CSRF-защита включается в компоненте `request` и обычно активна по умолчанию для web-приложений. Формы, созданные через `ActiveForm`, автоматически добавляют CSRF-токен.

Для защиты от XSS нужно экранировать пользовательский вывод:

```php
<?= \yii\helpers\Html::encode($model->title) ?>
```

Если нужно вывести HTML, его следует очищать через разрешенный sanitizer, например HTMLPurifier:

```php
<?= \yii\helpers\HtmlPurifier::process($model->content) ?>
```

SQL-инъекции предотвращаются использованием параметров, Query Builder или ActiveRecord:

```php
User::find()
    ->where(['email' => $email])
    ->one();
```

Нельзя склеивать SQL из пользовательского ввода:

```php
// Плохо
$sql = "SELECT * FROM user WHERE email = '$email'";
```

Также важны:

- корректная настройка cookie `httpOnly`, `secure`, `sameSite`;
- ограничение HTTP-методов через `VerbFilter`;
- проверка прав доступа на уровне действий и бизнес-операций;
- безопасная загрузка файлов;
- хранение паролей через `Yii::$app->security->generatePasswordHash()`.

## 12. Как правильно хранить и проверять пароли?

**Вопрос:**  
Как Yii2 рекомендует работать с паролями пользователей?

**Подробный ответ:**  
Пароли нельзя хранить в открытом виде или шифровать обратимым способом. Нужно хранить только хеш пароля.

Создание хеша:

```php
$user->password_hash = Yii::$app->security->generatePasswordHash($password);
```

Проверка:

```php
Yii::$app->security->validatePassword($password, $user->password_hash);
```

Методы Yii2 используют безопасные механизмы PHP для хеширования паролей. Это лучше, чем самостоятельно выбирать алгоритм, соль и параметры.

Дополнительно важно:

- не логировать пароли;
- не возвращать пароль или хеш в API;
- использовать HTTPS;
- ограничивать частоту попыток входа;
- инвалидировать токены при смене пароля, если это требуется политикой безопасности.

## 13. Как устроена маршрутизация в Yii2?

**Вопрос:**  
Как Yii2 сопоставляет URL с контроллером и action?

**Подробный ответ:**  
Маршрутизация выполняется компонентом `urlManager`. Без красивых URL маршрут может выглядеть так:

```text
/index.php?r=site/index
```

С включенным `enablePrettyUrl` URL становится более читаемым:

```text
/site/index
```

Пример настройки:

```php
'urlManager' => [
    'enablePrettyUrl' => true,
    'showScriptName' => false,
    'rules' => [
        'posts/<id:\d+>' => 'post/view',
        'POST api/orders' => 'api/order/create',
    ],
]
```

Правила URL позволяют задавать шаблоны, HTTP-методы, параметры и маршруты. В REST API часто используется `yii\rest\UrlRule`, который автоматически создает правила для CRUD-действий.

## 14. Как создать REST API на Yii2?

**Вопрос:**  
Какие классы Yii2 используются для REST API и как контролировать формат ответа?

**Подробный ответ:**  
Для REST API Yii2 предоставляет `yii\rest\Controller`, `yii\rest\ActiveController` и набор actions для CRUD.

Пример:

```php
class UserController extends \yii\rest\ActiveController
{
    public $modelClass = User::class;
}
```

Для маршрутов:

```php
'urlManager' => [
    'enablePrettyUrl' => true,
    'rules' => [
        [
            'class' => yii\rest\UrlRule::class,
            'controller' => 'user',
        ],
    ],
]
```

Формат ответа управляется компонентом `response`:

```php
'response' => [
    'format' => yii\web\Response::FORMAT_JSON,
]
```

Для контроля полей используются методы модели:

```php
public function fields()
{
    return ['id', 'email', 'created_at'];
}

public function extraFields()
{
    return ['profile'];
}
```

В реальном API также нужно учитывать аутентификацию, rate limiting, версионирование, коды ошибок, пагинацию, фильтрацию и контракты ответа.

## 15. Как работает аутентификация в Yii2?

**Вопрос:**  
Как Yii2 определяет текущего пользователя и что должен реализовать класс User?

**Подробный ответ:**  
Аутентификация в web-приложении обычно работает через компонент `user`. Он хранит идентификатор пользователя в сессии и загружает identity-класс.

Класс пользователя должен реализовать `yii\web\IdentityInterface`:

```php
class User extends ActiveRecord implements \yii\web\IdentityInterface
{
    public static function findIdentity($id) {}
    public static function findIdentityByAccessToken($token, $type = null) {}
    public function getId() {}
    public function getAuthKey() {}
    public function validateAuthKey($authKey) {}
}
```

Для входа:

```php
Yii::$app->user->login($user);
```

Для выхода:

```php
Yii::$app->user->logout();
```

В API часто используют token-based authentication: `HttpBearerAuth`, `QueryParamAuth` или собственный механизм. В таком случае `findIdentityByAccessToken()` должен находить пользователя по токену.

## 16. Как использовать behaviors в Yii2?

**Вопрос:**  
Что такое behaviors и приведите примеры их применения.

**Подробный ответ:**  
Behavior - это механизм Yii2 для добавления объекту дополнительного поведения без наследования. Behavior можно подключить к модели, контроллеру или компоненту.

Пример для автоматического заполнения временных меток:

```php
public function behaviors()
{
    return [
        [
            'class' => \yii\behaviors\TimestampBehavior::class,
            'createdAtAttribute' => 'created_at',
            'updatedAtAttribute' => 'updated_at',
        ],
    ];
}
```

Пример для контроллера:

```php
public function behaviors()
{
    return [
        'access' => [
            'class' => \yii\filters\AccessControl::class,
            'rules' => [
                [
                    'allow' => true,
                    'roles' => ['@'],
                ],
            ],
        ],
    ];
}
```

Behaviors полезны для повторяющихся технических задач: timestamps, blameable-поля, доступ, HTTP-методы. Бизнес-логику лучше выносить в явные сервисы, если behavior делает поведение неочевидным.


## 17. Как работать с транзакциями?

**Вопрос:**  
Когда нужна транзакция и как ее правильно использовать в Yii2?

**Подробный ответ:**  
Транзакция нужна, когда несколько операций с базой данных должны выполниться атомарно: либо все успешно, либо все откатываются.

Пример:

```php
$transaction = Yii::$app->db->beginTransaction();

try {
    $order->save(false);
    $payment->save(false);
    $transaction->commit();
} catch (\Throwable $e) {
    $transaction->rollBack();
    throw $e;
}
```

Транзакции особенно важны при создании заказов, списании баланса, изменении складских остатков и любых операциях, где частичное выполнение приводит к неконсистентным данным.

Важные моменты:

- не держать транзакцию дольше необходимого;
- не выполнять внутри транзакции долгие внешние HTTP-запросы без крайней необходимости;
- проверять результат `save()`, если используется валидация;
- использовать блокировки или ограничения БД там, где есть конкурентные изменения.

## 18. Как организовать бизнес-логику в Yii2-проекте?

**Вопрос:**  
Где должна находиться бизнес-логика: в контроллере, модели или сервисе?

**Подробный ответ:**  
Контроллер должен принимать запрос, вызывать нужный сценарий приложения и возвращать ответ. Он не должен содержать сложные бизнес-правила.

ActiveRecord может содержать логику, тесно связанную с конкретной сущностью: вычисляемые свойства, связи, простые проверки состояния. Но если операция затрагивает несколько сущностей или описывает бизнес-процесс, ее лучше вынести в сервис.

Пример:

```php
class OrderService
{
    public function createOrder(CreateOrderForm $form): Order
    {
        // Создание заказа, позиций, резервирование остатков,
        // публикация события или постановка задачи в очередь.
    }
}
```

Такой подход упрощает тестирование, уменьшает размер контроллеров и делает бизнес-операции явными.

## 19. Как искать и исправлять проблемы производительности в Yii2?

**Вопрос:**  
Какие инструменты и подходы вы используете для оптимизации Yii2-приложения?

**Подробный ответ:**  
Сначала нужно измерить проблему, а не оптимизировать вслепую. В Yii2 помогают:

- Yii Debug Toolbar;
- лог SQL-запросов;
- профилирование через `Yii::beginProfile()` и `Yii::endProfile()`;
- slow query log на стороне базы данных;
- APM-инструменты;
- анализ индексов через `EXPLAIN`.

Типичные причины медленной работы:

- N+1 запросы;
- отсутствие индексов;
- выборка лишних колонок;
- загрузка слишком больших связанных графов моделей;
- тяжелая логика во view;
- отсутствие пагинации;
- неоптимальная сериализация API-ответов;
- повторные вычисления без кэша.

Типичные решения:

- использовать `with()` или `joinWith()` осознанно;
- добавлять индексы под реальные фильтры и сортировки;
- выбирать только нужные поля через `select()`;
- использовать `asArray()` для read-only списков;
- применять кэширование;
- переносить тяжелые задачи в очередь;
- оптимизировать SQL-запросы.

## 20. Какие ошибки в Yii2-проектах вы считаете типичными?

**Вопрос:**  
Назовите распространенные архитектурные и технические ошибки в Yii2-проектах.

**Подробный ответ:**  
Типичные ошибки:

- слишком толстые контроллеры;
- вся бизнес-логика находится в ActiveRecord;
- отсутствие Form Model для сложных форм;
- SQL собирается строковой конкатенацией;
- игнорируются сценарии валидации;
- нет транзакций в критичных операциях;
- N+1 запросы;
- отсутствует пагинация в списках и API;
- миграции пишутся без учета больших таблиц;
- права доступа проверяются только во view, а не на сервере;
- данные пользователя выводятся без экранирования;
- кэш добавляется без стратегии инвалидации;
- отсутствуют тесты на ключевые бизнес-сценарии.
